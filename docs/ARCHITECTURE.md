# Архитектура игры

Короткая карта кода в `game/scripts`: кто за что отвечает и куда вносить
изменения. У каждого вида компонента (СУ, машина, игровая система, сетевое
состояние) один контракт и один реестр, а не `if` по всему коду.

## Папки

Скрипты разложены по предметной области; в одной папке не больше ~15–20 файлов.
Таблицы ниже называют файлы по имени, папку можно найти здесь.

| Папка `game/scripts/…` | Что внутри |
| --- | --- |
| `core/` | Точка сборки `game.gd`, процедурные модели `props.gd`, слияние мешей, звук, дальность прорисовки. |
| `stages/` | Общая обвязка СУ: `stage.gd`, контракт биома, реестр, лес, коллизии, записи, индекс маршрута. |
| `stages/<СУ>/` | Биом и декорации одного СУ: `forest_pass`, `winter` (с глубоким снегом и сугробами), `village`, `canyon`, `finnish_forest` (с озёрами), `mineshaft`. |
| `people/` | Люди: риг поз, зрители и их навигация, маршалы и судьи, сбитые и медики. |
| `player/` | Локальный игрок: движение, взаимодействие, действия, на что можно залезть, грибы и пиво. |
| `camp/` | Лагерь: расстановка, мангал, готовка, сбор, модели мангала и стола. |
| `cars/` | Машины игрока: реестр, кузов, колёса, багажник, управляемость, поездки и буксир, отдельные модели. |
| `traffic/` | Машины на трассе: раллийные экипажи и их траектории, расписание, полиция, скорая, парки сервиса. |
| `net/` | Комната: протокол, транспорт, WebRTC, синхронизация мира, предсказание и вид других игроков. |
| `platform/` | Платформа и браузер: VK/веб-сервис, захват курсора, DOM-ввод, сцены-пробы для веб-тестов. |
| `ui/` | Интерфейс: HUD, меню, UI-кит, мобильное управление, миникарта, памятка, локализация. |

Тесты `game/tests/` лежат в тех же папках (плюс `previews/` для рендеров
превью); `harness.gd` и вспомогательные сцены сетевых тестов — в корне.
Реестр шардов `scripts/test-catalog.mjs` перечисляет тесты по имени файла,
папку раннер находит сам. Инструменты `game/tools/` разделены на `bake/`,
`assets/`, `profile/` и `screenshots/`.

## Сборка мира

| Файл | Роль |
| --- | --- |
| `game.gd` | Точка сборки: создаёт мир, комнату и системы, держит общее состояние сессии, раздаёт кадр системам. Внешний API (`toggle_car()`, `show_toast()` …) — однострочные делегаты. |
| `rally_crews.gd` | ИИ экипажей, гравий из-под колёс, буксировка. |
| `player_motion.gd` | Игрок: ходьба, прыжок, вождение, камера, посадка в машину, опьянение. |
| `perches.gd` | На что можно запрыгнуть и встать: машины, стол, стул, лежащий человек, ящики `stage_solids`, камни. Форма объекта — карта высот из его же мешей (одна на набор мешей, общая для одинаковых машин), поэтому новый предмет подключается одной строкой `Perches.mark(node)`. Верх до 0,25 м над ногами — шаг, в прыжке на спуске — до 0,35 м (с земли достаётся ≈1,2 м: капот, стол, забор; с капота — крыша), выше — стена. Стоящий на машине едет с ней; в состоянии игрока `stand` (ключ машины `car:<id>` / `racer:<id>`) и `stand_at` (ноги в её системе координат), каждый клиент ставит человека на свою копию машины. |
| `car_rides.gd` | Машина друга: посадка пассажиром (до 5 человек с водителем), трос между машинами (T за рулём), сломанная машина больше не едет; выезд окончен, только когда разбиты все машины. Выбор игрока идёт в его состоянии (`ride`, `hitch`, `broken`). |
| `camp_actions.gd` | Лагерь: расстановка мебели, мангал, еда, напитки. |
| `game_hud.gd` | HUD и окно меню: карточки HUD, тосты, главное меню / пауза / итог в одном окне, безопасные зоны, кнопки приглашения и дальности. |

Система — `RefCounted` с полем `game`. Состояние остаётся в `game.gd`, система
его читает и меняет. Новая игровая механика — новая система, а не новые
функции в `game.gd`.

## Подвижные предметы

`prop_registry.gd` явно регистрирует реквизит; интерьеры, детали на столах и
палатки сервиса остаются статичными. `movable_props.gd` управляет взаимодействиями
и прежними снимками `movable_props`, а `prop_body.gd` передаёт движение и сон GodotPhysics3D.
Игровой узел сохраняется; отдельные коллайдеры стула оставляют свободное место
между ножками и спинкой. `prop_ground.gd` создаёт общие тайлы физического рельефа
по мере движения предметов, `prop_actors.gd` обновляет коллайдеры существующих
кинематических машин и людей. Физика работает у хозяина; у гостей тела заморожены
и получают полную позу из снимка. Обновление лагеря сохраняет эту позу, а явное
ручное размещение переносит и игровой узел, и тело. Покой определяет движок:
выравнивания по вертикали, прижима к земле и остановки по одному порогу скорости нет.

## Интерфейс

| Файл | Роль |
| --- | --- |
| `ui_kit.gd` | Единый вид: палитра, шкала шрифтов (`title`, `heading`, `body`, `caption`, `muted`, `hud`), кнопки `primary` / `secondary` / `ghost` / `toggle` через тему, модальное окно `modal()`, блок бренда `brand()` (логотип RFM, название, «от Rally Fans Map»), адрес сайта. |
| `lobby_ui.gd` | Главное меню: карточки машины и СУ с покупкой под своей колонкой, «О нас» и «Помощь», громкость, баннер паузы хозяина, фон меню. |
| `room_lobby.gd` | Блок «Выезд» (ник, создать, войти по ID) и строка комнаты в карточке СУ. |
| `how_to_play.gd` | Раздел «Как играть»: четыре вкладки (цель, управление, лагерь, ралли), управление для текущего устройства. В VK открывается один раз перед памяткой безопасности при первом входе на СУ (`user://how_to_play.cfg`), всегда — из паузы кнопкой «Как играть». |
| `pointer_capture.gd` | Мышь на ПК: камера поворачивается только при захваченном курсоре; браузер снял захват (Esc, переключение окна) — открывается пауза; пока игра идёт без захвата — подсказка «Кликни по экрану». |
| `mobile_controls.gd` | Телефон: стики в нижних углах, сетка плиток над правым стиком (`grid_rect`), педали, ящик лагеря над карточкой статуса. Все плитки рисуются одной функцией: иконка и подпись. |

Экран не задаёт цвета и размеры шрифта сам: он берёт роль из `ui_kit.gd`.
Главное меню, пауза и итог — одно окно (`game.menu`); `game_hud.update_menu()`
решает, какие его части видны, `layout_menu()` вписывает окно в безопасную
зону (на телефоне — за вычетом выреза и панели VK). Снимки всех состояний для
проверки раскладки: `tools/screenshots/export_ui_screenshots.gd` (см. шапку файла).

## СУ (спецучастки)

| Файл | Роль |
| --- | --- |
| `data/stages.json` | Реестр СУ: id, название, скрипт биома, небо, солнце, туман, подпись ягод, цвет миникарты. Порядок = `content_id` в каталоге. |
| `stage_registry.gd` | Читает реестр: `captions()`, `section(i, "environment")`, `make_biome(i)`. |
| `stage_biome.gd` | Контракт СУ. Все хуки со значениями по умолчанию (обычный гравийный лесной СУ). |
| `stage.gd` | Общая обвязка: индекс маршрута, рельеф и дорога, коллизии, собираемое, судьи. Сам ничего не знает о конкретных СУ. |
| `stage_forest.gd` | Единственный генератор леса: хвойный лес по хукам биома, лесная подстилка (трава, камни, валуны, кусты, ягоды, грибы, муравейники), деревья-слои деревни и инстансные слои деталей. |
| `detail_layer.gd` | Типизированное описание слоя деталей: тайлы, дальность, собираемый, текстура, группа падающего дерева. |
| `stage_records.gd` | Конструкторы записей `stage.rocks[]` и `stage.collectibles[]`. Записи остаются словарями: их хранят запечённые сцены и снимки комнаты. |
| `forest_pass.gd`, `alpine_winter.gd`, `village_stage.gd`, `canyon.gd`, `finnish_forest.gd` | Биомы пяти СУ. |

### Как добавить СУ

1. Создать `scripts/stages/<id>/<id>.gd` с `extends "res://scripts/stages/stage_biome.gd"`.
   Обязателен `route(s)`, остальное — только то, что отличается от лесного
   СУ по умолчанию: рельеф (`base_ground` или `land_relief`), дорога
   (`road_width`, `road_color`), сцепление, лес (`forest_tree_count`),
   декорации (`build_details`), правила ходьбы и лагеря.
2. Добавить запись в конец `stages` в `data/stages.json`.
3. Добавить товар `type: "stage"` с тем же `content_id` и названием в
   `data/store_catalog.json`.

Сервер, меню, превью, миникарта и циклы тестов берут список СУ из реестра.
`tests/protocol.test.mjs` проверяет, что реестр, каталог и биомы согласованы
и что в `stage.gd` нет веток по конкретным СУ.

Общие подсистемы включаются хуками, а не проверкой имени СУ:
`has_snow()` — глубокий снег и лопата, `outfit()` — во что одеты люди
(по умолчанию `"winter"` на снежных СУ), `make_water()` — озёра и плавучесть,
`sync_providers()` — своё сетевое состояние мира (например, снег).

## Машины

| Файл | Роль |
| --- | --- |
| `data/cars.json` | Парк игрока: внешний вид, управляемость, багажник. Индекс = `content_id`, новые машины только в конец. |
| `car_registry.gd` | Читает парк, подставляет `defaults`, `rear_bias()` из типа привода. |
| `props.gd` | `player_car()` строит модель по записи: собственный конструктор (`model`) или общий кузов. `rally_car()`, `course_car()` — раллийный парк и машины трассы. `trunk_profile()` — из `trunk`. |
| `car_body.gd` | Единственный процедурный кузов: общие машины игрока, весь раллийный парк и полиция. Профиль (размеры, `shape`, оптика, решётка, диски, расширители, антикрыло…) → кузов и замеры для ливреи. Список полей — в шапке файла. |
| `service_traffic.gd` | Полиция и скорая: уступают людям, страховочная остановка перед человеком. Скорая с правом проезда: простояла 2,5 с — 30 м едет в приоритете (до 5 м/с): объезжает машины по обочине, а если места нет — проезжает сквозь машины, камни и уличные предметы; людей объезжает или ждёт. |
| `character_profiles.gd` | Кто эти люди: двенадцать обликов, десять мужских и два женских (лицо, причёска, очки, усы и борода, имя, летняя одежда) и комплекты одежды `OUTFITS` (сейчас `winter`: пуховик, шарф, варежки, утеплённые штаны, сапоги, шапка). Генератор `tools/assets/character_source.gd` запекает GLB на каждый облик и комплект, `Props.player_avatar(variant, outfit)` берёт нужный, руки от первого лица (`beer_hand`, `meat_hand`) одеваются так же. Комплект выбирает СУ: `stage.outfit` из `biome.outfit()`, его передают все, кто создаёт людей. |
| `character_rig.gd` | Позы всех людей: игроки у других в комнате, зрители, маршалы и судьи, медик, жители деревни, пострадавшие. Вызывающий описывает действие (`gait`, `seat`, `kneel`, `arms`: еда, пиво, коробка, лопата, толкать, флаг, болеть…), риг выставляет все суставы: бёдра и колени, плечи и локти. Кисти ставятся двухзвенной IK в точки вне тела, поэтому руки не проходят сквозь торс и голову. Лист поз для проверки: `tools/screenshots/export_character_poses.gd`. |
| `injuries.gd` | Сбитые люди: удар машины → полёт тела на физике движка (`RigidBody3D` над участком `HeightMapShape3D`) → лежит → скорая (машина трассы `ambulance`) со старта, красный флаг → лечение → игрок хромает. Решает хозяин комнаты, гости получают раздел `injuries` снимка. |
| `mesh_merge.gd` | Запекание реквизита в один меш с цветами вершин (`bake`) и сведение многоматериальных мешей (`flatten`). Машины запекаются в `Props.bake_car()`. Подробности и замеры — `docs/RENDER_PERFORMANCE.md`. |
| `block_text.gd` | Блочный шрифт 5×7 из треугольников: надписи, которые запекаются вместе с поверхностью. |
| `car_parts.gd` | Колесо для всех машин: шина, диск и рисунок (спицы, отверстия, прорези) одним мешем с вершинными цветами на одном шарнире, поэтому вращение видно. `hub_holes()` — отверстия для импортированных колёс-«блинов». |
| `data/rally_cars.json` + `rally_car_model.gd` | Раллийный парк: профиль кузова + ливрея (номер, спонсор, `livery`, такси). Индекс = `variant` в снимках комнаты — только в конец. Там же порядок старта, нулевые экипажи и полиция. |
| `granta_model.gd`, `niva_asset.gd`, `camping_hatchback_asset.gd` | Собственные модели Гранты, Нивы (OBJ, плоские нормали) и 2112 (OBJ). Их колёса тоже вращаются вокруг `LEFT`: верх протектора уходит вперёд. |
| `player_handling.gd` | `profile()` — из `handling`. |

### Как добавить машину

1. Дописать запись в `cars` в `data/cars.json`. Для общего кузова нужны
   `shape` (6 чисел: стойки, крыша, задние стёкла, колёса) и размеры. Для
   своей модели — `model` и ветка в `Props.player_car()`.
2. Добавить товар `type: "car"` с тем же `content_id` и названием в
   `data/store_catalog.json`.

Раллийная машина — запись в конец `cars` в `data/rally_cars.json` и её номер в
`spawn_order`. Кода не нужно. Проверить взглядом:
`xvfb-run godot --path game --script res://tools/screenshots/export_car_sheet.gd -- out.png rally`.

## Сеть

Хозяин симулирует мир, гости присылают состояние и команды. `data/net_protocol.json` описывает протокол, лимиты и формат id комнаты один раз; его читают и GDScript, и Worker.

| Путь | Что несёт | Как |
| --- | --- | --- |
| Сервер комнаты (Durable Object) | членство, команды и их подтверждения, медленные секции мира (лагерь, зрители, снег…), запасной путь для всего остального | WebSocket, если сокет держится; иначе HTTP-опрос |
| Прямой канал (`direct_link.gd`) | гость → хозяин: состояние и неподтверждённый ввод руля (30 раз/с); хозяин → гость: горячий мир, авторитетные машины, состояния всех (20 раз/с, 10 при 4+ гостях) | WebRTC data channel без упорядочивания и повторов: потерянный пакет перекрывает следующий |

Прямой канал есть только в браузерной сборке. Гость звонит хозяину, когда открыт сокет комнаты; сервер передаёт offer/answer/ICE только между хозяином и гостем (`signal` в `worker.mjs`) и ничего не хранит. Пока по каналу приходят пакеты (`stale`, 0,5 с), гость шлёт в синхронизации `direct: true`, и сервер доставляет ему только медленные секции и состав (ответ помечен `world.direct`, состояния игроков `null`); замолчавший канал сразу возвращает всё на серверный путь: следующая синхронизация уходит без флага и получает полный мир. Если хозяин свёрнут (`background`) или молчит, сервер шлёт полный мир с `paused` и при живом канале. Не открывшийся канал (NAT, корпоративная сеть) повторяется через 20 с, не больше трёх раз. TURN не используется: где прямое соединение невозможно, игра остаётся на сервере.

Рация (`voice_chat.gd`) — голос между любыми участниками комнаты. Звук идёт через бэкенд: в браузере `web/voice-chat.js` (`voice_web.gd`), на desktop и Android — GDExtension `native/voice` (`voice_native.gd`). Оба говорят на одном WebRTC и одном сигналинге, поэтому браузерные и нативные игроки слышат друг друга. Каждая пара участников держит своё WebRTC-соединение (mesh, до `max_players`). Звонит участник с меньшим id, второй отвечает на аудиолинию из offer. Сервер пересылает сигналы с `space: "voice"` между любыми двумя членами комнаты, а не только хозяин ↔ гость. У них свои лимиты (`voice` в `net_protocol.json`), а `kind` и `session` проверяются. Звук через сервер не идёт. Микрофон запрашивается при первом нажатии X (кнопка «Рация» на телефоне). Без доступа к микрофону рация работает на приём. Пока клавиша зажата и микрофон открыт, в состоянии игрока стоит `radio: true`: остальные видят позу с рацией и строку «РАЦИЯ · имя», а на приёме включаются помехи. Громкость, полоса и шум зависят от расстояния: полосы заданы в `voice.bands` в `net_protocol.json`, а JS-копию сверяет тест. Godot читает результаты JS только JSON-строкой: `JavaScriptBridge.eval` возвращает лишь примитивы. Нативная библиотека едет внутри pack и загружается при первом входе в рацию (подробнее в `native/voice/README.md`). Без неё рация скрыта.

Хозяин проверяет состояние из прямого канала теми же правилами, что и сервер (`NetProtocol.clean_state`). Формы снимков мира заданы в `game/data/world_schema.json`: Worker и `world_validation.gd` проверяют их целиком до изменения мира, включая холодные секции и WebRTC. При изменении провайдера обновляйте схему и общие фикстуры `game/tests/fixtures/world_snapshots.json`; отсутствующие поля частичного снимка сохраняют прежние значения по умолчанию.

Ошибки транспорта и ответы 5xx по HTTP/WebSocket сохраняют членство, команды,
подтверждения и ввод предсказания: повторяем с задержкой 1–5 секунд в течение
45 активных секунд от первой ошибки (монотонные часы, без времени потери фокуса),
затем показываем ошибку и закрываем
выезд. Это оставляет запас до серверного TTL членства 90 секунд с учётом таймаута
HTTP 8 секунд. Ошибка сокета 5xx или отсутствие ответа на отправленную
синхронизацию 8 секунд переводит синхронизацию на HTTP. Успешный ответ
или снимок сервера сбрасывает период восстановления. 401/404/410 и ошибки данных
400/413 завершают выезд с сообщением сервера; 429 отдельно откладывает отправку
на `retry_after`, без счётчика ошибок транспорта.

### Что в проводе (протокол 8)

- Сервер не пускает гостя с другой `protocol_version`, чем у хозяина комнаты: формат мира меняется между версиями, а старая закэшированная сборка иначе молча разошлась бы с новой.
- Стоящий на машине передаёт не только `pos`, но и `stand` + `stand_at` (ключ машины и ноги в её системе координат): иначе из-за задержки его видно в нескольких метрах позади едущей машины. Пустой `stand` в пакет не попадает.
- Пакет прямого канала не повторяет состав (имя, слот, машина приходят с сервера), а состояние игрока сжато `NetProtocol.compact_state()`: значения по умолчанию, поля только для хозяина (`drive_inputs`, `trees`, `lamps`), `car` водителя (равен `pos`) и средний угол `tilt` (равен `heading`) не отправляются, `expand_state()` возвращает их на госте.
- Поля мира, которые лежат на значении «по умолчанию» (`paused`, `racing`, `passed`, `helped`, `dead`, `finished`, `cook_time` = -1, пустые `impacts` и `recovery_links`), в снимок не попадают; гость читает отсутствующее поле как значение по умолчанию.
- `driving` округляется (мм, 0,1 мрад) и без полей, которые `restore()` и так считает значением по умолчанию.
- Камни гравия: полное состояние идёт только пока камень новый (`STONE_FRESH_MSEC`, 0,2 с), остальное время гость сам летит им (`advance_gravel`); `stone_ids` — id всех живых камней, пропавшие из списка удаляются.
- Зрители и маршалы без `yaw`, если не помогают машине: гость сам поворачивает их к дороге / ближайшему экипажу. `course.remaining` округляется вверх до секунды, чтобы секция расписания не менялась каждый кадр во время отсчёта.
