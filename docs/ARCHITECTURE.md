# Архитектура игры

Короткая карта кода в `game/scripts`: кто за что отвечает и куда вносить
изменения. У каждого вида компонента (СУ, машина, игровая система, сетевое
состояние) один контракт и один реестр, а не `if` по всему коду.

## Сборка мира

| Файл | Роль |
| --- | --- |
| `game.gd` | Точка сборки: создаёт мир, комнату и системы, держит общее состояние сессии, раздаёт кадр системам. Внешний API (`toggle_car()`, `show_toast()` …) — однострочные делегаты. |
| `rally_crews.gd` | ИИ экипажей, гравий из-под колёс, буксировка. |
| `player_motion.gd` | Игрок: ходьба, прыжок, вождение, камера, посадка в машину, опьянение. |
| `car_rides.gd` | Машина друга: посадка пассажиром (до 5 человек с водителем), трос между машинами (T за рулём), сломанная машина больше не едет; выезд окончен, только когда разбиты все машины. Выбор игрока идёт в его состоянии (`ride`, `hitch`, `broken`). |
| `camp_actions.gd` | Лагерь: расстановка мебели, мангал, еда, напитки. |
| `game_hud.gd` | HUD и окно меню: карточки HUD, тосты, главное меню / пауза / итог в одном окне, безопасные зоны, кнопки приглашения и дальности. |

Система — `RefCounted` с полем `game`. Состояние остаётся в `game.gd`, система
его читает и меняет. Новая игровая механика — новая система, а не новые
функции в `game.gd`.

## Интерфейс

| Файл | Роль |
| --- | --- |
| `ui_kit.gd` | Единый вид: палитра, шкала шрифтов (`title`, `heading`, `body`, `caption`, `muted`, `hud`), кнопки `primary` / `secondary` / `ghost` / `toggle` через тему, модальное окно `modal()`, блок бренда `brand()` (логотип RFM, название, «от Rally Fans Map»), адрес сайта. |
| `lobby_ui.gd` | Главное меню: карточки машины и СУ с покупкой под своей колонкой, «О нас» и «Помощь», громкость, баннер паузы хозяина, фон меню. |
| `room_lobby.gd` | Блок «Выезд» (ник, создать, войти по ID) и строка комнаты в карточке СУ. |
| `how_to_play.gd` | Раздел «Как играть»: четыре вкладки (цель, управление, лагерь, ралли), управление для текущего устройства. В VK открывается один раз перед памяткой безопасности при первом входе на СУ (`user://how_to_play.cfg`), всегда — из паузы кнопкой «Как играть». |
| `pointer_capture.gd` | Мышь на ПК: камера поворачивается только при захваченном курсоре; браузер снял захват (Esc, переключение окна) — открывается пауза; пока игра идёт без захвата — подсказка «Кликни по экрану». |
| `mobile_controls.gd` | Телефон: стики в нижних углах, сетка плиток над правым стиком (`grid_rect`), педали, ящик лагеря над карточкой статуса. Все плитки рисуются одной функцией: иконка и подпись. |

Экран не задаёт цвета и размеры шрифта сам: он берёт роль из `ui_kit.gd`.
Главное меню, пауза и итог — одно окно (`game.menu`); `game_hud.update_menu()`
решает, какие его части видны, `layout_menu()` вписывает окно в безопасную
зону (на телефоне — за вычетом выреза и панели VK). Снимки всех состояний для
проверки раскладки: `tools/export_ui_screenshots.gd` (см. шапку файла).

## СУ (спецучастки)

| Файл | Роль |
| --- | --- |
| `data/stages.json` | Реестр СУ: id, название, скрипт биома, небо, солнце, туман, подпись ягод, цвет миникарты. Порядок = `content_id` в каталоге. |
| `stage_registry.gd` | Читает реестр: `captions()`, `section(i, "environment")`, `make_biome(i)`. |
| `stage_biome.gd` | Контракт СУ. Все хуки со значениями по умолчанию (обычный гравийный лесной СУ). |
| `stage.gd` | Общая обвязка: индекс маршрута, рельеф и дорога, коллизии, собираемое, судьи. Сам ничего не знает о конкретных СУ. |
| `stage_forest.gd` | Единственный генератор леса: хвойный лес по хукам биома, лесная подстилка (трава, камни, валуны, кусты, ягоды, грибы, муравейники), деревья-слои деревни и инстансные слои деталей. |
| `detail_layer.gd` | Типизированное описание слоя деталей: тайлы, дальность, собираемый, текстура, группа падающего дерева. |
| `stage_records.gd` | Конструкторы записей `stage.rocks[]` и `stage.collectibles[]`. Записи остаются словарями: их хранят запечённые сцены и снимки комнаты. |
| `forest_pass.gd`, `alpine_winter.gd`, `village_stage.gd`, `canyon.gd`, `finnish_forest.gd` | Биомы пяти СУ. |

### Как добавить СУ

1. Создать `scripts/<id>.gd` с `extends "res://scripts/stage_biome.gd"`.
   Обязателен `route(s)`, остальное — только то, что отличается от лесного
   СУ по умолчанию: рельеф (`base_ground` или `land_relief`), дорога
   (`road_width`, `road_color`), сцепление, лес (`forest_tree_count`),
   декорации (`build_details`), правила ходьбы и лагеря.
2. Добавить запись в конец `stages` в `data/stages.json`.
3. Добавить товар `type: "stage"` с тем же `content_id` и названием в
   `data/store_catalog.json`.

Сервер, меню, превью, миникарта и циклы тестов берут список СУ из реестра.
`tests/protocol.test.mjs` проверяет, что реестр, каталог и биомы согласованы
и что в `stage.gd` нет веток по конкретным СУ.

Общие подсистемы включаются хуками, а не проверкой имени СУ:
`has_snow()` — глубокий снег и лопата, `make_water()` — озёра и плавучесть,
`sync_providers()` — своё сетевое состояние мира (например, снег).

## Машины

| Файл | Роль |
| --- | --- |
| `data/cars.json` | Парк игрока: внешний вид, управляемость, багажник. Индекс = `content_id`, новые машины только в конец. |
| `car_registry.gd` | Читает парк, подставляет `defaults`, `rear_bias()` из типа привода. |
| `props.gd` | `player_car()` строит модель по записи: собственный конструктор (`model`) или общий кузов. `rally_car()`, `course_car()` — раллийный парк и машины трассы. `trunk_profile()` — из `trunk`. |
| `car_body.gd` | Единственный процедурный кузов: общие машины игрока, весь раллийный парк и полиция. Профиль (размеры, `shape`, оптика, решётка, диски, расширители, антикрыло…) → кузов и замеры для ливреи. Список полей — в шапке файла. |
| `service_traffic.gd` | Полиция и скорая: уступают людям, страховочная остановка перед человеком. Скорая с правом проезда: простояла 2,5 с — 30 м едет в приоритете (до 5 м/с): объезжает машины по обочине, а если места нет — проезжает сквозь машины, камни и уличные предметы; людей объезжает или ждёт. |
| `character_rig.gd` | Позы всех людей: игроки у других в комнате, зрители, маршалы и судьи, медик, жители деревни, пострадавшие. Вызывающий описывает действие (`gait`, `seat`, `kneel`, `arms`: еда, пиво, коробка, лопата, толкать, флаг, болеть…), риг выставляет все суставы: бёдра и колени, плечи и локти. Кисти ставятся двухзвенной IK в точки вне тела, поэтому руки не проходят сквозь торс и голову. Лист поз для проверки: `tools/export_character_poses.gd`. |
| `injuries.gd` | Сбитые люди: удар машины → полёт тела на физике движка (`RigidBody3D` над участком `HeightMapShape3D`) → лежит → скорая (машина трассы `ambulance`) со старта, красный флаг → лечение → игрок хромает. Решает хозяин комнаты, гости получают раздел `injuries` снимка. |
| `mesh_merge.gd` | Запекание реквизита в один меш с цветами вершин (`bake`) и сведение многоматериальных мешей (`flatten`). Машины запекаются в `Props.bake_car()`. Подробности и замеры — `docs/RENDER_PERFORMANCE.md`. |
| `block_text.gd` | Блочный шрифт 5×7 из треугольников: надписи, которые запекаются вместе с поверхностью. |
| `car_parts.gd` | Колесо для всех машин: шина, диск и рисунок (спицы, отверстия, прорези) одним мешем с вершинными цветами на одном шарнире, поэтому вращение видно. `hub_holes()` — отверстия для импортированных колёс-«блинов». |
| `data/rally_cars.json` + `rally_car_model.gd` | Раллийный парк: профиль кузова + ливрея (номер, спонсор, `livery`, такси). Индекс = `variant` в снимках комнаты — только в конец. Там же порядок старта, нулевые экипажи и полиция. |
| `granta_model.gd`, `niva_asset.gd`, `camping_hatchback_asset.gd` | Собственные модели Гранты, Нивы (OBJ, плоские нормали) и 2112 (OBJ). Их колёса тоже вращаются вокруг `LEFT`: верх протектора уходит вперёд. |
| `player_handling.gd` | `profile()` — из `handling`. |

### Как добавить машину

1. Дописать запись в `cars` в `data/cars.json`. Для общего кузова нужны
   `shape` (6 чисел: стойки, крыша, задние стёкла, колёса) и размеры. Для
   своей модели — `model` и ветка в `Props.player_car()`.
2. Добавить товар `type: "car"` с тем же `content_id` и названием в
   `data/store_catalog.json`.

Раллийная машина — запись в конец `cars` в `data/rally_cars.json` и её номер в
`spawn_order`. Кода не нужно. Проверить взглядом:
`xvfb-run godot --path game --script res://tools/export_car_sheet.gd -- out.png rally`.

## Сеть

Хозяин симулирует мир, гости присылают состояние и команды. `data/net_protocol.json` описывает протокол, лимиты и формат id комнаты один раз; его читают и GDScript, и Worker.

| Путь | Что несёт | Как |
| --- | --- | --- |
| Сервер комнаты (Durable Object) | членство, команды и их подтверждения, медленные секции мира (лагерь, зрители, снег…), запасной путь для всего остального | WebSocket, если сокет держится; иначе HTTP-опрос |
| Прямой канал (`direct_link.gd`) | гость → хозяин: состояние и неподтверждённый ввод руля (30 раз/с); хозяин → гость: горячий мир, авторитетные машины, состояния всех (20 раз/с, 10 при 4+ гостях) | WebRTC data channel без упорядочивания и повторов: потерянный пакет перекрывает следующий |

Прямой канал есть только в браузерной сборке. Гость звонит хозяину, когда открыт сокет комнаты; сервер передаёт offer/answer/ICE только между хозяином и гостем (`signal` в `worker.mjs`) и ничего не хранит. Пока по каналу приходят пакеты (`stale`, 0,5 с), сервер для этого гостя доставляет только медленные секции и членство; замолчавший канал сразу возвращает всё на серверный путь. Не открывшийся канал (NAT, корпоративная сеть) повторяется через 20 с, не больше трёх раз. TURN не используется: где прямое соединение невозможно, игра остаётся на сервере.

Хозяин проверяет состояние из прямого канала теми же правилами, что и сервер (`NetProtocol.clean_state`).

## Проверки

- `node scripts/lint-gdscript.mjs` — статические проверки без Godot:
  пути `preload()`, отступы, запрещённые в веб-шаблоне модули, записи и слои
  только через `stage_records.gd` / `detail_layer.gd`, бюджет размеров
  (`scripts/gdscript-budget.json`). Бюджет только уменьшается.
- `node scripts/test-game.mjs --shard=core|simulation|world` — функциональные
  тесты Godot по реестру `scripts/test-catalog.mjs`.
