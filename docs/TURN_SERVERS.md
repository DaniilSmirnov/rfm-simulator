# TURN-ретрансляторы для прямых соединений

Игра идёт по прямому каналу WebRTC между хозяином комнаты и каждым гостем
(`game/scripts/net/direct_link.gd`). Сервер комнат держит только состав комнаты
и передаёт сообщения для установки канала. Если сеть одного из игроков не
пропускает прямой канал (строгий NAT, CGNAT мобильного оператора, фильтры
провайдера), гость видит «Не удалось соединиться». TURN-ретранслятор
пересылает трафик через себя, и канал открывается и в таких сетях.

Ретрансляторы — это **свои серверы с coturn**, не Cloudflare. Причина в том,
что российские провайдеры режут трафик к Cloudflare и к подсетям зарубежных
хостингов. Ретрансляторов может быть сколько угодно и где угодно. Сервер
комнат только выдаёт к ним временные пароли.

## Как это устроено

1. В настройках сервера комнат лежит список ретрансляторов `TURN_SERVERS` и
   общий секрет `TURN_SECRET` (у каждого ретранслятора может быть свой).
2. В ответ на создание комнаты и на вход сервер добавляет поле `ice`:
   2–3 ретранслятора для этого игрока с паролем
   (`server/relays.mjs`). Сначала идут ретрансляторы для страны игрока
   (Cloudflare сообщает страну в `request.cf.country`), затем общие, а
   более тяжёлые по `weight` идут раньше. Ретрансляторы с одинаковым весом
   перемешиваются, чтобы нагрузка распределялась.
3. Пароли сделаны по схеме coturn `use-auth-secret` («TURN REST API»):
   логин `<срок действия unix>:<игрок>`, пароль
   `base64(HMAC-SHA1(секрет, логин))`, срок действия 12 часов. coturn
   проверяет их сам, поэтому ему не нужны ни база, ни связь с сервером комнат.
4. Клиент добавляет эти серверы к STUN из `net_protocol.json`. Дальше WebRTC
   сам пробует все варианты: если прямой канал открывается, ретранслятор не
   используется и трафика не тратит.

Старые клиенты поле `ice` не читают. Новые клиенты со старым сервером
работают как раньше, только через STUN.

### Ограничения нативных сборок

Нативный канал (`native/voice`, libdatachannel + libjuice) умеет TURN **только
по UDP** и использует не больше двух TURN-серверов (они выбираются случайно).
Поэтому `voice_native.gd` `ice_urls()` оставляет первые два UDP-ретранслятора,
а пароль кладёт прямо в URL (`turn:логин:пароль@хост:порт`, всё в
URL-кодировке). TURN по TLS на 443 работает только в браузерной (VK) сборке.

## Поднять ретранслятор

Нужен VPS с публичным IP: 1 vCPU и 1 ГБ RAM хватит на сотни игроков. Подойдёт
российский хостинг (Selectel, Timeweb, Yandex Cloud, VK Cloud) или любой другой.

```sh
# На сервере, из копии папки server/turn:
openssl rand -hex 32            # это будет TURN_SECRET
cat > .env <<EOF
TURN_SECRET=<секрет>
# Только если у VPS внутренний адрес за 1:1 NAT (Yandex Cloud, AWS):
# TURN_EXTERNAL_IP=<публичный IP>/<внутренний IP>
# Для TURN по TLS на 443 (браузеры за жёсткими фильтрами):
# TURN_CERT=/etc/letsencrypt/live/turn1.example.ru/fullchain.pem
# TURN_KEY=/etc/letsencrypt/live/turn1.example.ru/privkey.pem
EOF
docker compose up -d --build
```

Порты в файрволе: `3478/udp`, `3478/tcp`, `443/tcp` (если включён TLS) и
диапазон ретрансляции `49160-49999/udp`.

Сертификат можно получить через `certbot certonly --standalone -d turn1.example.ru`.
Контейнер работает не от root, поэтому сделай ключ читаемым: например, через
deploy-hook скопируй `fullchain.pem` и `privkey.pem` в отдельную папку с
правами `644` и укажи её в `TURN_CERT` и `TURN_KEY`.

Проверка: открой https://webrtc.github.io/samples/src/content/peerconnection/trickle-ice/,
впиши `turn:turn1.example.ru:3478`, логин и пароль из ответа `/api/rooms/…/join`
(поле `ice`) и нажми «Gather candidates». В списке должен появиться кандидат `relay`.

Настройки в `server/turn/turnserver.conf`:
- ретранслятор не пересылает трафик в частные сети (защита от доступа к сети хостинга);
- TCP-ретрансляция выключена;
- на одно соединение не больше 2 Мбит/с, на одного игрока не больше 16
  соединений. Это намного больше, чем нужно игре, но не даёт использовать
  ретранслятор как бесплатный прокси.

## Подключить ретранслятор к серверу комнат

```sh
npx wrangler secret put TURN_SECRET
```

В `wrangler.jsonc` → `vars` (или в настройках Worker в Cloudflare) добавь:

```json
"TURN_SERVERS": "[{\"id\":\"msk-1\",\"urls\":[\"stun:turn1.example.ru:3478\",\"turn:turn1.example.ru:3478?transport=udp\",\"turn:turn1.example.ru:3478?transport=tcp\",\"turns:turn1.example.ru:443?transport=tcp\"],\"countries\":[\"RU\",\"BY\",\"KZ\"],\"weight\":1}]"
```

Поля одного ретранслятора:
- `urls`: адреса `stun:`, `turn:`, `turns:` (с `?transport=udp|tcp`);
- `countries`: страны, игроки из которых получат его в первую очередь. Если
  поле пустое, ретранслятор для всех. Игрокам из других стран
  ретранслятор, привязанный к странам, не выдаётся;
- `weight`: порядок среди равных (по умолчанию 1, при 0 ретранслятор выключен);
- `secret`: имя переменной с секретом этого ретранслятора (по умолчанию
  `TURN_SECRET`), например `TURN_SECRET_SPB`.

Ещё две настройки: `TURN_PICK` (сколько ретрансляторов получает игрок, по
умолчанию 3) и `TURN_TTL` (срок жизни пароля в секундах, по умолчанию 43200).

Чтобы добавить или убрать ретранслятор, достаточно поменять `TURN_SERVERS` и
выкатить Worker. Новая сборка игры не нужна.

## Телеметрия: сколько соединений не открывается

Гость сообщает серверу, чем кончилась проверка связи
(`game/scripts/net/link_report.gd` → `POST /api/telemetry/link`). Worker
пишет в лог одну строку `[RFM link] {...}`:

| поле | что значит |
|---|---|
| `result` | `linked` (канал открылся), `failed` (не открылся при входе), `lost` (пропал во время игры) |
| `reason` | для `failed`: `blocked` (сети не пропускают), `host_silent`, `no_socket` (не прошёл сокет к серверу комнат), `no_webrtc` |
| `local`, `remote` | типы кандидатов гостя и хозяина: `host`, `srflx` (адрес через STUN), `relay` (через TURN) |
| `pair` | пара, по которой реально идёт канал (только нативные сборки), например `relay/host` |
| `relays` | сколько ретрансляторов выдали игроку |
| `country`, `asn`, `network` | страна и сеть (оператор), из которых пришёл запрос |
| `platform`, `waited`, `attempts` | платформа, сколько секунд ждали, сколько было попыток |

Смотреть в Cloudflare → Workers → rally-fans-simulator → Logs, фильтр по
`[RFM link]`. Основные вопросы:
- доля `failed` среди всех отчётов, по `country` и `network`;
- `failed` с `reason: no_socket`: игрок не достучался до самого сервера комнат,
  и TURN тут не поможет;
- `linked` с `pair`, начинающимся на `relay`: этих игроков спас ретранслятор;
- `failed`, где в `local` нет `srflx`: у игрока не работает даже STUN.

Отчёт идёт тем же путём, что и запросы к серверу комнат. Поэтому если сервер
комнат недоступен совсем, отчёт тоже не дойдёт.

## Сколько это стоит

Канал игры — это десятки кбит/с на гостя (пакеты мира 10–20 раз в секунду),
плюс рация, пока нажата кнопка. Час игры через ретранслятор — это порядка
десятков мегабайт. VPS за 300–1000 ₽ в месяц с включённым трафиком хватит с
большим запасом. Через ретранслятор идут только те, у кого прямой канал не
открылся.

## Что TURN не решает

- Сервер комнат (сокет и `/api`) пока остаётся на Cloudflare. Если у игрока
  недоступен он сам, в логах это будет `reason: no_socket`, или отчёта не
  будет вовсе. Следующий шаг: на тех же VPS поднять прокси для `/api` и
  сокета и дать клиенту список зеркал.
- В режиме «белых списков» у мобильных операторов наружу пропускают только
  сервисы из списка. Ни сервер комнат, ни ретранслятор там не будут доступны,
  пока они не в списке.
