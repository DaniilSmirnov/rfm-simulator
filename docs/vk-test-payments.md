# Покупки контента VK

По умолчанию включён `VK_PAYMENTS_MODE: "production"`.
Все 7 платных машин (`car_04`–`car_10`) стоят 3 голоса,
3 платных СУ (`stage_02` — Зимний Турини, `stage_03` — Виноградники, `stage_04` — Красный каньон) — по 20 голосов.
Бесплатными остаются три базовые машины и `stage_01` (Лесной перевал). В обычной веб-версии все СУ доступны без VK-покупки.
Источник товаров и цен — `game/data/store_catalog.json`.

## Реальные платежи

Worker требует `VK_APP_SECRET` и привязку Durable Object `PAYMENTS`.
В кабинете VK включить реальные платежи и постоянный URL уведомлений:
`https://rally-fans-simulator.di-719.workers.dev/api/vk/payments/callback`.

Клиент запрашивает `/api/vk/payments/prepare` с Bearer-сессией и открывает
`VKWebAppShowOrderBox` с SKU. Результат окна не выдаёт права: игра ждёт
подтверждённую сервером покупку и обновляет `/api/vk/store`.

`get_item` возвращает цену каталога. `order_status_change` со статусом
`chargeable` проверяет подпись, приложение, пользователя, SKU и стоимость,
затем атомарно сохраняет заказ. Повторное уведомление идемпотентно;
конфликтующие данные, подарки и неверная стоимость отклоняются.
Маркер ответа: `X-Rally-Payments-Handler: vk-content-callback-v6`.
Сервер проверяет права при создании комнаты и выборе личной машины.

## Тестовый режим и миграция

Для проверки без реальной оплаты установить `VK_PAYMENTS_MODE: "test"` и
`VK_PAYMENTS_TEST_USERS` в список ID через запятую (`*` разрешает всех).
Необязательный `VK_STAGE_02_TEST_PRICE` переопределяет цену всех тестовых
товаров для совместимости. Без него применяются цены каталога.
Тестовая выдача возможна только через `order_status_change_test`;
описание товара поддерживает `get_item_test` и `get_item`.

Тестовые и реальные заказы разделены ключом `(mode, order_id)` в SQLite.
Тестовые права никогда не открывают товары в реальном режиме.
Старые SQL-заказы и подтверждённые KV-заказы сохраняются при автоматической
миграции. Переключение режима не удаляет покупки. Режим `disabled` скрывает
покупки и платные права до повторного включения соответствующего режима.

## Проверка и SQL

`npm run test:vk`: цены, подписи, все платные товары, повторные уведомления,
разделение режимов, миграция и серверные права.
`game/tests/test_lobby_ui.gd`: кнопки покупки и цены 3/20 голосов.

После production-деплоя проверить в VK отмену заказа, реальную покупку,
приход callback, доступ к товару и сохранение покупки после перезапуска.
Коммит сам по себе не подтверждает успешный деплой или приём оплаты в VK.

Cloudflare → Durable Objects → `VkPayments` → Data Studio, объект
`vk:54809523`. Таблица `payment_orders` содержит подтверждённые заказы:

```sql
SELECT * FROM payment_orders ORDER BY created_at DESC;
SELECT * FROM payment_orders WHERE mode = 'production' AND user_id = '87478742';
```

Удаление заказа отзывает право, если нет другого заказа на тот же SKU.
Повторный подписанный callback может восстановить удалённый заказ.
Не удалять маркер `kv_orders_v1` из `payment_migrations`: он предотвращает
повторный импорт старой резервной копии.
Одежда, персонажи и предметы пока не представлены отдельными SKU.

## Красный каньон (stage_04)

«Красный каньон» в VK стоит **20 голосов**. После подтверждённого `order_status_change` для `item_id=stage_04` права хранятся в VK Durable Object и восстанавливаются при повторном входе. До оплаты выбор СУ для просмотра разрешён, но кнопка создания комнаты и старт недоступны; игрок увидит кнопку «ОТКРЫТЬ СУ · 20 ГОЛОСОВ». Подключение гостем к чужой комнате с каньоном остаётся бесплатным (без передачи права собственности).

Платёж не начисляется на клиенте: только подписанный callback VK с верными товаром и ценой даёт доступ к `stage_04`. В локальной/test конфигурации цена тестовых платежей может переопределяться `VK_STAGE_02_TEST_PRICE` для всех тестовых товаров; production всегда проверяет **20**.
