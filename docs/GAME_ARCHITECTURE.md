# Границы игровых систем

Этот рефакторинг сохраняет Godot 4.4.1, HTTP-комнаты с авторитетным хостом и совместное пространство комнат для standalone/VK.

## Состояние и представление

- `player_state.gd`: личные данные игрока (движение, здоровье, опьянение, еда, прыжок).
- `world_state.gd`: общее состояние выезда, лагеря и восстановления машин.
- `session_state.gd`: жизненный цикл MENU → LOADING → PLAYING → DEAD/FINISHED. Причины локальной и хостовой паузы независимы; снятие одной не снимает другую.
- `game_ui.gd`: построение игровых панелей и обновление HUD.
- `room_ui.gd`: создание интерфейса комнаты.
- `room_transport.gd`: HTTP, ограничения ответа, размеры исходящих и входящих сообщений.
- `world_snapshot.gd`: создание полного снимка и восстановление визуальных объектов.
- `command_executor.gd`: игровые действия с явным `actor_context.gd`.
- `vehicle_simulation.gd`: единственный фиксированный шаг движения, столкновений, повреждений и подвески для локальной машины, авторитетного расчёта гостя и предсказания.
- `game/data/player_models.json`: описания автомобилей, отделённые от генерации геометрии.

`game.gd` остаётся координатором и содержит другие механики. Его прежние свойства и методы делегируют новым компонентам, чтобы не ломать ввод, контроллы и существующие сценарии. Новую общую механику следует добавлять в профильный сервис, а не создавать второй источник состояния в координаторе. Продолжение разделения генерации сцен, NPC и раллийных машин возможно независимо от этих контрактов.

## Команды

`submit()` возвращает успех только при фактическом добавлении действия в очередь. В гостевом режиме отказ очереди не запускает локальную замену общего действия. Подтверждение приёма сервером (`accepted`) отличается от результата выполнения хостом.

Исполнитель возвращает `applied`, `rejected` с причиной или `deferred`. Пауза хоста откладывает команду без ACK; после продолжения команда исполняется. Завершённый выезд и недоступное действие дают отказ. Повторы неполученного ACK не исполняются снова. Хост хранит только текущие неподтверждённые идентификаторы; сервер хранит последние 64 результата, которые возвращаются соответствующему гостю. Отказ виден через уведомление.

Контекст гостя передаётся в инвентарь, размещение, уборку, сбор и потребление еды. Он не меняет позицию, машину, взгляд или состояние еды хоста. Локальный контекст переиспользуется; сетевые команды получают отдельный снимок контекста.

## Снимки мира

Единый декларативный контракт: `game/data/world_protocol.json`. Его читают валидаторы Godot и Worker; тестовый `world_v1.json` общий для обоих рантаймов. Проверяются обязательные поля, типы, конечные числа, диапазоны, размеры коллекций и вложенные структуры. Worker проверяет снимок до изменения состояния участника. Клиент проверяет его до предсказания и восстановления сцены.

`world_protocol = 1` обозначает контракт, `generation_version = 1` — совместимость индексов генерируемых объектов. При несовместимом изменении идентификаторов/генерации нужно повысить generation_version и обновить контракт вместе с клиентом и Worker. При несовместимом изменении формата повышается world_protocol.

Worker принимает ограниченные снимки старого формата без версии для переходного развёртывания; новый клиент требует v1. Вход в старую комнату завершается понятным предложением обновить страницу, а не частичным применением данных. Клиент и Worker следует выпускать одной сборкой. Неизвестные поля в v1 отклоняются; новые поля необходимо явно добавлять в контракт.

## Проверки

- `npm run test:unit`: Node-тесты и изолированные правила/физика Godot без построения полной карты.
- `npm run test:integration`: сцены, комнаты, лагерь, интерфейс и взаимодействия.
- `npm test`: оба набора.
- `node scripts/test-game.mjs --suite=integration --from=test_room`: прогон интеграционных сценариев начиная с указанного теста для продолжения диагностики.

Ошибки GDScript в выводе тестового процесса считаются провалом даже при коде выхода 0. Проверки комнаты покрывают переполнение, паузу/продолжение, повтор, освобождение ACK и неизменность данных хоста. Изолированная проверка физики сравнивает одинаковые тики при различном группировании ввода.

## Производительность и дальнейшие границы

Снимки пока полные. Каждые 5 секунд диагностика комнаты выводит RTT, jitter, размеры отправки/ответа и максимум отправленного сообщения. Переход к дельтам должен опираться на замеры и сохранять поздний вход и повторную синхронизацию. Порог API — 64 KiB, лимит ответа движка — 128 KiB.

Этот рефакторинг не переносит симуляцию на сервер и не вводит миграцию хоста. Браузерные fetch-обёртки остаются адаптацией минимального экспортного движка; их отдельная замена требует проверки standalone/VK и фонового heartbeat.
